# Как обосновать отличия CCRQS и пользу объединения компонентов

Дата: 07.10.2026. Основа — спецификация CCRQS v4 и уточнение пользователя о центральном вкладе в виде самого критерия. Ниже — конкретные сравнения и заготовки для proposal, а не результаты проведённого эксперимента.

## 1. Два разных основания научного вклада

**Отличие от литературы:** какой объект и каким способом измеряет ваш критерий, в чём его конструкция отличается от ближайших аналогов.

**Добавочная польза:** что эта конструкция позволяет лучше или дополнительно оценивать на данных. Для критерия, заявленного как приближение к экспертному суждению, основной проверяемый аргумент — согласованность с независимой оценкой относительно более простых способов измерения.

Отличие не требует изобретения каждого слагаемого с нуля. Новая обоснованная комбинация известных измерений может быть исследовательским вкладом, если её свойства и область применения установлены. Однако произвольное новое название или новый набор весов не доказывают необходимость такого инструмента.

## 2. С чем действительно сопоставлять CCRQS

Сравнение только с BLEU будет неполным. При целевом поиске именно **оценочных критериев** выделились следующие ближайшие работы:

| Подход | Основная рассмотренная процедура | Отличие CCRQS v4, которое можно проверить по спецификациям |
|---|---|---|
| [CRScore](https://aclanthology.org/2025.naacl-long.457/) | Оценивает содержание review через соответствие утверждениям и проблемам, извлечённым из кода; объединяет conciseness/comprehensiveness в relevance и проверяет согласованность с людьми | D опирается на подтверждённый основной дефект; Q отдельно оценивает собственный patch автора review по исполнению и экспертной проверке |
| [DeepCRCEval](https://arxiv.org/html/2412.18291v2) | Люди и LLM оценивают комментарии по девяти признакам, включая объяснение, обнаружение проблемы и actionability, и ранжируют результаты | В CCRQS часть результата проверяется применением patch, целевыми и регрессионными тестами; итоговая формула и процедура настройки весов заданы явно |
| [CR-Evaluator / CR-Bench](https://arxiv.org/html/2603.11078v1) | Разделяет попадание в эталонный bug, valid suggestions и noise; считает обнаружение и usefulness | CCRQS дополнительно включает качество собственного исправления; scope замечаний отличается, поэтому одинаковые названия precision/usefulness не означают одинаковые метрики |
| [c-CRAB](https://arxiv.org/html/2603.23448v3) | Отдельный coding agent исправляет код по review; результат оценивается тестами | Q проверяет patch, предложенный самой оцениваемой моделью; C измеряется отдельно от patch |
| [GradedReviews / Deep Assessment](https://arxiv.org/abs/2501.05176v1) | Семантическая оценка generated/reference review и сопоставление с человеческими баллами | CCRQS опирается также на проверяемое поведение кода; качество patch не выводится только из сходства текстов |

Таблица сравнивает **рассмотренные основные процедуры**, а не утверждает отсутствие соответствующих идей во всей литературе. Источники для новых строк: CRScore — NAACL 2025, § 3–5; DeepCRCEval — HTML v2, § 4.1 и 5.1; Deep Assessment — аннотация и metadata, полный метод здесь ещё не проверен.

Вывод из этого сопоставления: «многомерная оценка с экспертной валидацией» уже имеет предшественников. Предполагаемое отличие CCRQS точнее искать в **операционализации оценки полного структурированного результата review + proposed patch и эмпирически обоснованной агрегации**. Сам по себе Python, локальный запуск или русский язык комментариев — границы применения, а не доказательство методической новизны.

Для окончательного related work по каждой работе выписать: объект оценки; доступный ground truth; компоненты; способ агрегации; калибровку; участие человека; проверку patch; независимость validation; ограничения. Если признак ещё не установлен, писать «не проверено», а не ставить «нет».

## 3. Сформулировать отличия именно вашей конструкции

В v4 уже есть четыре конкретных свойства:

1. **Единица оценки — полный ответ одной модели на один экземпляр кода.** Обнаружение, комментарий и собственный patch связаны с одним эталонным дефектом.
2. **Компонент Q имеет проверяемые условия:** `Q = A × T × R × S`. Неприменимый patch или неустранённый целевой отказ дают Q=0; прошедшие тесты дополняются смысловой оценкой.
3. **Текст объяснения и patch оцениваются раздельно.** При оценке C patch не показывается; хороший код не должен автоматически повысить качество комментария.
4. **Агрегация калибруется по общему экспертному суждению**, затем замораживается и проверяется на других проектах.

Это фактические свойства v4. Считать каждое из них впервые предложенным нельзя без дополнительной сверки. Возможный вклад — их обоснованное сочетание и проверенные свойства итогового критерия.

Различие с c-CRAB имеет цену: отказ от отдельного fixer снимает один источник зависимости, но собственный patch требует от reviewer навыка исправления. Поэтому CCRQS измеряет review **с предлагаемым исправлением**, а не только полезность текста. Не заявлять, что такая оценка универсально превосходит оценку reviewer→fixer.

## 4. Проверить, нужны ли три компонента

Для одних и тех же ответов test-выборки собрать независимый общий экспертный балл E. Затем сравнить:

| Оценка | Какой вопрос проверяет |
|---|---|
| D отдельно | Достаточно ли измерить обнаружение? |
| C отдельно | Достаточно ли качества объяснения? |
| Q отдельно | Достаточно ли качества исправления? |
| `(D+C+Q)/3` | Нужен ли подбор весов вместо простой суммы? |
| CCRQS с настроенными весами | Как согласуется полный критерий с экспертами? |
| CCRQS без C | Даёт ли C информацию сверх D и Q? |
| CCRQS без Q | Даёт ли Q информацию сверх D и C? |
| CCRQS без D | Даёт ли D информацию сверх C и Q? |

Последние три варианта — **абляции**, то есть проверки с исключением компонента. Они не требуют новых ответов моделей. Каждый сокращённый вариант имеет неотрицательные веса с суммой 1; веса подбираются только на той же калибровочной выборке и по тому же правилу, после чего замораживаются. Это сравнение с заново настроенными сокращёнными критериями. Отдельное механическое обнуление веса с перенормировкой остальных допустимо как анализ чувствительности, но отвечает на другой вопрос.

Например, для проверки C:

`Δ_C = ρ(CCRQS, E) − ρ(CCRQS без C, E)`.

Положительная точечная разность сама по себе недостаточна для устойчивого вывода. Нужен интервал этой **парной разности на тех же ответах** с учётом группировки по задачам и репозиториям. Нельзя считать интервалы двух корреляций независимыми и судить только по их пересечению. При малом числе проектов precision такой проверки ограничена.

Чтобы не выбирать победителя на test, заранее определить первичный baseline, например D. Если требуется сравнить с «лучшим отдельным компонентом», его выбрать на калибровочных проектах и затем зафиксировать. Остальные сравнения обозначить вторичными и учесть множественность проверок.

Веса, которые стабильно становятся нулевыми, — сигнал, что на этом корпусе компонент не добавляет полезной информации. Это результат, который следует описать; наличие трёх слагаемых не нужно сохранять любой ценой.

## 5. Почему одного порога ρ≥0,75 недостаточно

**Условный пример, не экспериментальные числа:** у CCRQS корреляция с экспертами 0,80, у D — 0,85. Тогда абсолютная гипотеза о сильной связи может выполняться, но преимущество сложного критерия перед обнаружением не показано.

Другой условный результат: CCRQS — 0,82, равные веса — 0,81, интервал разности включает как положительные, так и отрицательные значения. Это не доказывает полезность настройки весов и не устанавливает эквивалентность методов. Возможен вклад в самом измерительном протоколе, но эмпирическую необходимость калибровки заявлять нельзя.

Нельзя сравнить ρ собственного CCRQS с опубликованной корреляцией CRScore или другой метрики на **другом** корпусе и объявить превосходство. Нужны общие ответы, одинаковая независимая экспертная цель и явное описание адаптации. Comment-only метрика и экспертный критерий полного ответа имеют разный scope; худшая согласованность первой с качеством полного ответа ещё не доказывает её плохое качество для комментариев.

CCRQS v4 также использует экспертные C и S. Его нельзя объявлять более эффективным автоматическим оценщиком на основании сравнения с полностью автоматической метрикой. Участие человека, время разметки и доступ к ground truth фиксировать отдельно.

## 6. Показать дополнительную различающую способность

Предлагаемая проверка — заранее выделить пары ответов на **одну и ту же задачу**, у которых одинаков D, но различаются C или Q. Независимые эксперты сравнивают общую полезность ответов, не видя компонентных баллов.

Иллюстрация для равных весов:

| Ответ | D | C | Q | CCRQS |
|---|---:|---:|---:|---:|
| A: дефект найден, объяснение конкретное, patch не устраняет отказ | 1 | 1 | 0 | 2/3 |
| B: дефект найден, объяснение конкретное, patch проходит проверки и смысловую оценку | 1 | 1 | 1 | 1 |

D не различает эти ответы. CCRQS различает, если вес Q положителен. Это **демонстрация поведения формулы**, а не доказательство её полезности: последняя проверяется предпочтением независимых экспертов на реальных парах. Если эксперты выбирают B, критерий способен отразить различие, потерянное в D. Аналогично исследуются пары с одинаковыми D и Q, но разными C.

Пары отбираются по заранее заданному правилу, не по удобному экспертному исходу. Для редких сочетаний может не хватить наблюдений — тогда публикуется размер подгруппы и отсутствие возможности уверенного вывода. Искусственно изменённые комментарии/patch допустимы только как отдельно маркированные диагностические случаи, не как дополнительные реальные ответы моделей.

Частота согласования ранжирования с экспертным предпочтением, доля связок и характер ошибок дают практическую интерпретацию наряду с корреляцией. D с равными значениями действительно не даёт ранжирования; не назначать ему автоматически случайный выбор и не трактовать появление любого ранга как победу CCRQS.

## 7. Дополнительная проверка, специфичная для v4

При ненайденном дефекте D=C=Q=0. Поэтому полную корреляцию дополнить анализом среди ответов с найденным дефектом и, где возможно, среди ответов с одинаковым D. Иначе связь с экспертами может преимущественно объясняться разделением «нашёл / не нашёл».

Важен и отрицательный контроль: **неверный patch не гарантирует низкий общий CCRQS**. При D=C=1, Q=0 и равных весах итог всё ещё 2/3. Поэтому нельзя описать Q как запрет на высокий общий балл опасного ответа. Проверить, возникают ли расхождения, когда эксперты считают patch вредным, а взвешенная сумма остаётся сравнительно высокой. Если да, это граница компенсаторной формулы и основание для отдельно обоснованного изменения конструкции в следующей версии, а не для молчаливой правки после test.

## 8. Заготовки для proposal

### Проблема

> Существующие подходы оценивают содержание комментариев, обнаружение известных дефектов либо результат исправления кода по review. В данной работе проверяется необходимость и валидность совместной оценки обнаружения, объяснения и собственного предлагаемого исправления в одном структурированном ответе локальной LLM. Требуется установить, даёт ли такая агрегация дополнительную согласованность с независимыми экспертными суждениями относительно отдельных компонентов и варианта с равными весами.

### Предполагаемая новизна

> Предполагаемый научный вклад состоит в разработке и валидации критерия CCRQS для оценки полного результата code review с предлагаемым patch. Критерий связывает оценку обнаружения подтверждённого дефекта, отдельную схему оценки комментария и проверку собственного исправления по применимости, целевым и регрессионным тестам и смысловой корректности. Научная проверка включает калибровку весов по независимой целостной экспертной оценке, тестирование на других проектах и анализ добавочной информативности компонентов.

Это более конкретный кандидат на вклад, но окончательное утверждение новизны должно опираться на расширенное сопоставление близких методов.

### Более конкретная H2

> CCRQS с весами, зафиксированными на калибровочных проектах, демонстрирует на независимых тестовых проектах более высокую согласованность с целостной экспертной оценкой, чем заранее выбранный компонентный baseline. Дополнительная польза C и Q проверяется абляциями и согласованностью ранжирования ответов с одинаковым D с независимыми экспертными предпочтениями.

H1 с порогом ρ≥0,75 можно оставить как абсолютную гипотезу. H2 отвечает на другой вопрос — **что добавляет новая конструкция**. Первичный baseline, допустимый практически значимый выигрыш и статистическое правило фиксируются до test. Не требуется обещать, что все сравнения обязательно покажут преимущество.

## 9. Минимальная работа для такого уточнения

1. Добавить предметную таблицу близких методов; CRScore и DeepCRCEval включить обязательно как ближайшие критерии оценки комментариев.
2. Уточнить объект как полный ответ review + proposed patch и конкретные особенности D/C/Q.
3. На тех же данных рассчитать компоненты, равные веса, полный и сокращённые критерии; новых генераций моделей для этого не требуется.
4. Провести предусмотренную v4 независимую экспертную оценку; отдельно проверить различия при одинаковом обнаружении.
5. По результатам разделить подтверждённую валидность, доказанную добавочную пользу и ограничения. Не достигнутый выигрыш тоже публикуется.

Агентное сравнение ни для одного из этих шагов не обязательно.
