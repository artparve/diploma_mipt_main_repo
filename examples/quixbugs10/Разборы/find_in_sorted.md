# Бинарный поиск


## Шаг 1 Исходный код QuixBugs

```python
def find_in_sorted(arr, x):
    def binsearch(start, end):
        if start == end:
            return -1
        mid = start + (end - start) // 2
        if x < arr[mid]:
            return binsearch(start, mid)
        elif x > arr[mid]:
            return binsearch(mid, end)
        else:
            return mid

    return binsearch(0, len(arr))
```

Файл: `python_programs/find_in_sorted.py`. Номера строк замечаний относятся к полному исходному файлу; копия сохранена в `data/QuixBugs/python_programs/find_in_sorted.py`.

## Шаг 2 Что проверяющий знает об ошибке

Правая ветка оставляет mid в интервале, поэтому поиск может не завершиться.

Наглядный вход: `find_in_sorted([1, 3, 5], 4)`. Ожидается `-1`. Это поясняющий пример, а A/T/R ниже рассчитаны по тестам из зафиксированного манифеста.

В манифесте: 2 целевых и 5 регрессионных тестов. Эталон и тесты служат материалами оценивания.

## Шаг 3 Ответ Gemma

```text
При поиске справа диапазон может не уменьшаться, потому что mid повторно попадает в рекурсивный вызов. Из-за этого возможна бесконечная рекурсия. Следует сдвинуть левую границу.
```

## Шаг 3 Ответ Qwen-Coder

```text
Правая ветка вызывает binsearch(mid, end), сохраняя уже проверенный индекс. Если mid == start, интервал не сокращается. Замените на binsearch(mid + 1, end), сохранив полуинтервал [start, end).
```

Дополнительное замечание 2: «Если искомого значения нет справа, mid может повторяться и функция зациклится. Исключите mid из нового диапазона.»

Локализация: строка 9 исходного файла.

Предлагаемый patch:

```diff
--- a/python_programs/find_in_sorted.py
+++ b/python_programs/find_in_sorted.py
@@ -6,7 +6,7 @@
         if x < arr[mid]:
             return binsearch(start, mid)
         elif x > arr[mid]:
-            return binsearch(mid, end)
+            return binsearch(mid + 1, end)
         else:
             return mid
```
