# Максимальная сумма подсписка


## Шаг 1 Исходный код QuixBugs

```python
def max_sublist_sum(arr):
    max_ending_here = 0
    max_so_far = 0

    for x in arr:
        max_ending_here = max_ending_here + x
        max_so_far = max(max_so_far, max_ending_here)

    return max_so_far
```

Файл: `python_programs/max_sublist_sum.py`. Номера строк замечаний относятся к полному исходному файлу; копия сохранена в `data/QuixBugs/python_programs/max_sublist_sum.py`.

## Шаг 2 Что проверяющий знает об ошибке

Отрицательная накопленная сумма не сбрасывается, из-за чего теряется выгодное начало подсписка.

Наглядный вход: `max_sublist_sum([4, -5, 2, 1, -1, 3])`. Ожидается `5`. Это поясняющий пример, а A/T/R ниже рассчитаны по тестам из зафиксированного манифеста.

В манифесте: 4 целевых и 2 регрессионных тестов. Эталон и тесты служат материалами оценивания.

## Шаг 3 Ответ Gemma

```text
После отрицательного префикса текущая сумма остаётся отрицательной и мешает начать лучший подсписок заново. Сбрасывайте max_ending_here до нуля через max(0, max_ending_here + x).
```

Локализация: строка 7 исходного файла.

Предлагаемый patch:

```diff
--- a/python_programs/max_sublist_sum.py
+++ b/python_programs/max_sublist_sum.py
@@ -4,7 +4,7 @@
     max_so_far = 0
 
     for x in arr:
-        max_ending_here = max_ending_here + x
+        max_ending_here = max(0, max_ending_here + x)
         max_so_far = max(max_so_far, max_ending_here)
 
     return max_so_far
```
